# 05_SCHEMA_DESIGN.md

## System Context
You are creating the PostgreSQL database tables, relationships, and Pydantic schemas for **BloodBridge AI** using Supabase PostgreSQL.

---

## Relational Database Schema (SQLAlchemy 2.0 / SQLModel)

### Enum Definitions (PostgreSQL Native)
```sql
CREATE TYPE blood_group_enum AS ENUM ('A+', 'A-', 'B+', 'B-', 'AB+', 'AB-', 'O+', 'O-');
CREATE TYPE blood_component_enum AS ENUM ('Whole Blood', 'RBC', 'Platelets', 'Plasma', 'Cryoprecipitate');
CREATE TYPE request_status_enum AS ENUM ('PENDING', 'APPROVED', 'IN_TRANSIT', 'COMPLETED', 'CANCELLED');
CREATE TYPE user_role_enum AS ENUM ('ADMIN', 'BLOOD_BANK_MANAGER', 'HOSPITAL_STAFF', 'VIEWER');
```

### 1. `hospitals`
Stores metadata for participating hospitals and blood banks.

| Column | Type | Constraints | Description |
|--------|------|-------------|-------------|
| `id` | UUID | PRIMARY KEY, DEFAULT gen_random_uuid() | Unique identifier |
| `name` | VARCHAR(255) | NOT NULL | Hospital name |
| `code` | VARCHAR(50) | UNIQUE, NOT NULL | Short code (e.g., "CITY-001") |
| `address` | TEXT | | Full address |
| `city` | VARCHAR(100) | | City name |
| `state` | VARCHAR(100) | | State name |
| `latitude` | FLOAT | | For route optimization |
| `longitude` | FLOAT | | For route optimization |
| `contact_phone` | VARCHAR(20) | | Primary contact number |
| `contact_email` | VARCHAR(100) | | Primary contact email |
| `is_active` | BOOLEAN | DEFAULT TRUE | Soft delete flag |
| `created_at` | TIMESTAMP | DEFAULT NOW() | Record creation time |
| `updated_at` | TIMESTAMP | DEFAULT NOW() | Auto-updated on change |

**Indexes:**
- `idx_hospitals_code` ON `code` (for quick lookups)
- `idx_hospitals_location` ON `latitude, longitude` (for geo queries)
- `idx_hospitals_active` ON `is_active` (for filtering active hospitals)

### 2. `blood_inventory`
Tracks active blood units in stock per hospital.

| Column | Type | Constraints | Description |
|--------|------|-------------|-------------|
| `id` | UUID | PRIMARY KEY, DEFAULT gen_random_uuid() | Unique identifier |
| `hospital_id` | UUID | NOT NULL, FK → `hospitals.id`, ON DELETE CASCADE | Owning hospital |
| `blood_group` | blood_group_enum | NOT NULL | A+, O-, etc. |
| `component` | blood_component_enum | NOT NULL | Whole Blood, RBC, etc. |
| `units_available` | INTEGER | NOT NULL, DEFAULT 0, CHECK >= 0 | Units ready for use |
| `units_reserved` | INTEGER | NOT NULL, DEFAULT 0, CHECK >= 0 | Units reserved for surgeries |
| `expiry_date` | DATE | NOT NULL | Expiration date |
| `batch_id` | VARCHAR(100) | | Internal batch tracking |
| `donation_date` | DATE | | When donated |
| `last_updated` | TIMESTAMP | DEFAULT NOW() | Auto-updated |

**Indexes:**
- `idx_inventory_hospital_blood` ON `hospital_id, blood_group, component` (most common query)
- `idx_inventory_expiry` ON `expiry_date` (for expiry alerts)
- `idx_inventory_hospital` ON `hospital_id` (for hospital inventory lookups)

**Triggers:**
- Auto-update `last_updated` on any modification.

### 3. `historical_demand`
Time-series log of blood usage for ML model training.

| Column | Type | Constraints | Description |
|--------|------|-------------|-------------|
| `id` | UUID | PRIMARY KEY, DEFAULT gen_random_uuid() | Unique identifier |
| `hospital_id` | UUID | NOT NULL, FK → `hospitals.id`, ON DELETE CASCADE | Usage location |
| `blood_group` | blood_group_enum | NOT NULL | Blood type used |
| `component` | blood_component_enum | NOT NULL | Component type |
| `units_used` | INTEGER | NOT NULL, CHECK > 0 | Units consumed |
| `date` | DATE | NOT NULL | Date of usage |
| `day_of_week` | INTEGER | GENERATED ALWAYS AS (EXTRACT(DOW FROM date)) STORED | 0=Sun, 6=Sat |
| `is_weekend` | BOOLEAN | GENERATED ALWAYS AS (EXTRACT(DOW FROM date) IN (0,6)) STORED | Weekend flag |
| `is_emergency` | BOOLEAN | DEFAULT FALSE | Emergency usage flag |
| `department` | VARCHAR(100) | | e.g., "Trauma", "Surgery", "Oncology" |
| `created_at` | TIMESTAMP | DEFAULT NOW() | Record time |

**Indexes:**
- `idx_demand_hospital_date` ON `hospital_id, date` (for time-series queries)
- `idx_demand_training` ON `hospital_id, blood_group, component, date` (for ML training)
- `idx_demand_date` ON `date` (for global trend analysis)

### 4. `ai_predictions`
Stores outputs generated by the XGBoost / ML engine.

| Column | Type | Constraints | Description |
|--------|------|-------------|-------------|
| `id` | UUID | PRIMARY KEY, DEFAULT gen_random_uuid() | Unique identifier |
| `hospital_id` | UUID | NOT NULL, FK → `hospitals.id`, ON DELETE CASCADE | Target hospital |
| `blood_group` | blood_group_enum | NOT NULL | Predicted blood type |
| `component` | blood_component_enum | NOT NULL | Predicted component |
| `prediction_date` | DATE | NOT NULL | Date prediction was made |
| `predicted_shortage_units` | INTEGER | | Predicted shortage amount |
| `predicted_demand_next_7d` | INTEGER | | 7-day demand forecast |
| `predicted_demand_next_30d` | INTEGER | | 30-day demand forecast |
| `risk_score` | FLOAT | CHECK BETWEEN 0.0 AND 1.0 | 0=safe, 1=critical |
| `risk_level` | VARCHAR(20) | GENERATED ALWAYS AS (CASE WHEN risk_score >= 0.7 THEN 'CRITICAL' WHEN risk_score >= 0.4 THEN 'HIGH' WHEN risk_score >= 0.2 THEN 'MEDIUM' ELSE 'LOW' END) STORED | Human-readable risk |
| `confidence_score` | FLOAT | CHECK BETWEEN 0.0 AND 1.0 | Model confidence |
| `explanation_json` | JSONB | | SHAP/feature weights |
| `model_version` | VARCHAR(20) | DEFAULT 'v1.0' | Model identifier |
| `created_at` | TIMESTAMP | DEFAULT NOW() | Prediction timestamp |

**Indexes:**
- `idx_predictions_hospital` ON `hospital_id, created_at DESC` (latest predictions first)
- `idx_predictions_risk` ON `risk_score DESC` (for alert dashboards)
- `idx_predictions_date` ON `prediction_date` (for historical tracking)

## Pydantic Schema Models (Backend)

Use **SQLModel** to unify ORM and validation:

```python
from sqlmodel import SQLModel, Field
from typing import Optional, List
from datetime import date, datetime
from uuid import UUID, uuid4
from enum import Enum

class BloodGroup(str, Enum):
    A_POS = "A+"
    A_NEG = "A-"
    B_POS = "B+"
    B_NEG = "B-"
    AB_POS = "AB+"
    AB_NEG = "AB-"
    O_POS = "O+"
    O_NEG = "O-"

class BloodComponent(str, Enum):
    WHOLE_BLOOD = "Whole Blood"
    RBC = "RBC"
    PLATELETS = "Platelets"
    PLASMA = "Plasma"
    CRYO = "Cryoprecipitate"

class RequestStatus(str, Enum):
    PENDING = "PENDING"
    APPROVED = "APPROVED"
    IN_TRANSIT = "IN_TRANSIT"
    COMPLETED = "COMPLETED"
    CANCELLED = "CANCELLED"

class RiskLevel(str, Enum):
    LOW = "LOW"
    MEDIUM = "MEDIUM"
    HIGH = "HIGH"
    CRITICAL = "CRITICAL"

# Base models with shared fields
class HospitalBase(SQLModel):
    name: str = Field(max_length=255)
    code: str = Field(max_length=50, unique=True)
    address: Optional[str] = None
    city: Optional[str] = None
    state: Optional[str] = None
    latitude: Optional[float] = None
    longitude: Optional[float] = None
    contact_phone: Optional[str] = Field(default=None, max_length=20)
    contact_email: Optional[str] = Field(default=None, max_length=100)

class Hospital(HospitalBase, table=True):
    __tablename__ = "hospitals"
    id: Optional[UUID] = Field(default_factory=uuid4, primary_key=True)
    is_active: bool = Field(default=True)
    created_at: datetime = Field(default_factory=datetime.utcnow)
    updated_at: datetime = Field(default_factory=datetime.utcnow)

class HospitalCreate(HospitalBase):
    pass

class HospitalResponse(HospitalBase):
    id: UUID
    is_active: bool
    created_at: datetime

# Inventory schemas
class BloodInventoryBase(SQLModel):
    hospital_id: UUID
    blood_group: BloodGroup
    component: BloodComponent
    units_available: int = Field(ge=0)
    units_reserved: int = Field(default=0, ge=0)
    expiry_date: date
    batch_id: Optional[str] = None
    donation_date: Optional[date] = None

class BloodInventory(BloodInventoryBase, table=True):
    __tablename__ = "blood_inventory"
    id: Optional[UUID] = Field(default_factory=uuid4, primary_key=True)
    last_updated: datetime = Field(default_factory=datetime.utcnow)

class BloodInventoryResponse(BloodInventoryBase):
    id: UUID
    last_updated: datetime
    # Computed fields
    units_total: int = 0
    status: str = "SUFFICIENT"  # SUFFICIENT / LOW / CRITICAL
    days_until_expiry: Optional[int] = None

# Prediction schemas
class PredictionExplanation(SQLModel):
    top_features: List[dict]
    summary: str

class AIPredictionResponse(SQLModel):
    id: UUID
    hospital_id: UUID
    blood_group: BloodGroup
    component: BloodComponent
    predicted_demand_next_7d: int
    predicted_demand_next_30d: int
    risk_score: float
    risk_level: RiskLevel
    confidence_score: float
    explanation: PredictionExplanation
    created_at: datetime

# Redistribution schemas
class RedistributionRequestBase(SQLModel):
    source_hospital_id: UUID
    target_hospital_id: UUID
    blood_group: BloodGroup
    component: BloodComponent
    units: int = Field(gt=0)
    ai_confidence: Optional[float] = None
    ai_reasoning: Optional[str] = None
    estimated_travel_time_mins: Optional[int] = None
    distance_km: Optional[float] = None

class RedistributionRequest(RedistributionRequestBase, table=True):
    __tablename__ = "redistribution_requests"
    id: Optional[UUID] = Field(default_factory=uuid4, primary_key=True)
    status: RequestStatus = Field(default=RequestStatus.PENDING)
    requested_by: Optional[UUID] = None
    approved_by: Optional[UUID] = None
    approved_at: Optional[datetime] = None
    completed_at: Optional[datetime] = None
    tracking_notes: Optional[str] = None
    created_at: datetime = Field(default_factory=datetime.utcnow)
    updated_at: datetime = Field(default_factory=datetime.utcnow)

class RedistributionResponse(RedistributionRequestBase):
    id: UUID
    status: RequestStatus
    created_at: datetime
    updated_at: datetime
    source_hospital: Optional[HospitalResponse] = None
    target_hospital: Optional[HospitalResponse] = None
```

## Supabase-Specific Setup Notes

### Connection String Format
```
postgresql://postgres:[YOUR-PASSWORD]@db.[PROJECT-REF].supabase.co:5432/postgres
```

### Row Level Security (RLS) Policies (Optional but Recommended)
```sql
-- Enable RLS on tables
ALTER TABLE blood_inventory ENABLE ROW LEVEL SECURITY;
ALTER TABLE redistribution_requests ENABLE ROW LEVEL SECURITY;

-- Example: Users can only see their hospital's inventory
CREATE POLICY "Hospital staff see own inventory"
ON blood_inventory FOR SELECT
USING (hospital_id = current_setting('app.current_hospital_id')::UUID);
```

### Using Supabase REST API (Alternative to direct SQLAlchemy)
For simple CRUD, you can use Supabase's auto-generated REST API from the frontend:
```typescript
const supabase = createClient(url, anonKey);
const { data } = await supabase.from('blood_inventory').select('*').eq('hospital_id', id);
```
**Recommendation:** Use SQLAlchemy for complex AI/ML operations and transactions. Use Supabase client for real-time subscriptions (live inventory updates).
